# CSS Animations

Source: CSS/31.CSS_Animation

## Key points
- An animation runs by itself, without needing a hover or other trigger.
- `@keyframes` defines the stages of the animation, using `from`/`to` or percentages such as `0%` and `50%`.
- `animation-name` links an element to a `@keyframes` rule. The names must match exactly.
- `animation-duration` sets how long one cycle takes. `0s` disables it.
- `animation-delay` waits before starting. A negative value starts partway through the cycle.
- `animation-iteration-count` sets how many times it repeats, or `infinite` for endless.
- `animation-direction` can be `normal`, `reverse`, `alternate` (forward then back) or `alternate-reverse`.
- `animation-timing-function` sets the speed curve, with the same choices as transitions.
- `animation-fill-mode` controls styling before and after the run: `forwards` keeps the last keyframe, `backwards` applies the first during the delay, `both` does both, and `none` (default) does neither.
- The `animation` shorthand order is: name, duration, timing function, delay, iteration count, direction, fill mode, play state.
- Animating `opacity` and `transform` tends to be smoother.

## Syntax / example
```css
@keyframes fadeIn {
  from { opacity: 0; }
  to   { opacity: 1; }
}
.box {
  animation: fadeIn 0.5s ease 0.2s 1 normal forwards;
}
```

## Remember
- The `@keyframes` name must match `animation-name` exactly.
- Shorthand order: name, duration, timing function, delay, iteration count, direction, fill mode.
- `forwards` keeps the final state after the animation ends; the default `none` does not.
- Transitions need a trigger; animations do not.
