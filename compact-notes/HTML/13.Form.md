# HTML Forms

Source: HTML/13.Form

## Key points
- A `form` is a container for input controls; its data is sent to a server with GET or POST.
- `form` attributes: `action` (target URL), `method`, `enctype`, `autocomplete`, `name`, `novalidate`, `target`.
- `enctype` sets how data is packaged: `application/x-www-form-urlencoded` (default), `multipart/form-data` (file uploads), `text/plain` (rarely used).
- The `type` attribute of `input` decides what it looks like and checks, e.g. text, password, email, radio, checkbox, file, date, range.
- `label` with a `for` that matches an input's `id` names the field and helps accessibility.
- `select` with `option` and `optgroup` makes drop-downs; `textarea` makes multi-line text.
- `button` types are `button`, `submit` and `reset`.
- `fieldset` groups related fields and `legend` captions the group.
- `datalist` supplies suggestion options to an input through its `list` attribute.
- Submit buttons can override the form's settings with `formaction`, `formmethod`, `formenctype`, `formnovalidate` and `formtarget`.
- The `form` attribute links an input to a form by id, even when the input sits outside that form.
- Validation attributes such as `required`, `pattern`, `min`, `max` and `minlength` check data in the browser; the server should still validate.

## Syntax / example
```html
<form action="/upload.php" method="post" enctype="multipart/form-data">
  <label for="email">Email:</label>
  <input type="email" id="email" name="email" required>
  <input type="file" name="resume" accept=".pdf">
  <button type="submit">Upload</button>
</form>
```

## Remember
- Use `multipart/form-data` whenever a form uploads a file.
- `label` + matching `for`/`id` is the accessible way to name a field.
- `formnovalidate` skips browser validation for that one button only; the server must still validate.
